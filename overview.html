전체 그림과 규약

상자·선·번호를 누르면 오른쪽에 열린다파란 상자 = 처리·피처·모델점선 = 데이터 없이 순서만

기사 20개 응답 → 5개 보임 → 1개 열림이면 반환 기록 20줄, 유효 노출 5건, article_open 1건이 남는다. 번호는 장주현 님 흐름도 기준이다.

번호일어나는 일오가는 것이 페이지에서
0기사 생성 Job이 기사를 Cloud SQL에 저장제목, 본문, 카테고리, publisher_id, published_at규약 ⑦ (아직 없음)
0가상 독자가 접속·클릭브라우저 독자와 같은 형식의 요청과 행동 기록남은 결정
①프론트가 피드 요청reader_id, cursor규약 ①
②백엔드가 뉴스 DB에서 후보 기사 조회최신·인기 기준 후보 20~30개규약 ②
③백엔드가 추론 서버에 점수 요청request_id, reader_id, candidates, context규약 ②
④추론 서버가 Valkey에서 피처 조회rf:, af:, re:, ri: 키규약 ⑥
⑤추론 서버가 점수 순 목록을 응답ranked, defaulted, unscored, model_version규약 ②
⑥백엔드가 프론트에 기사 목록 응답request_id, 기사별 impression_id·position규약 ①
⑦반환 기록과 행동 기록을 로깅 서버로 전송반환 기록(impression), exposure, article_open, like, unlike규약 ③
⑧로깅 서버가 5분 파티션으로 GCS에 저장served/, actions/ JSONL규약 ④
⑨센서가 파티션을 확인하고 원본을 적재raw.served, raw.actions규약 ⑤
⑩중복 제거·정제 후 BigQuery에 적재clean.*, agg.*, feat.*규약 ⑤
⑪1시간마다 피처를 Valkey에 적재새 버전 키를 쓰고 feat:current 교체규약 ⑥
⑫지표 집계CTR·체류대시보드 미정
⑬학습 데이터를 학습 Job에 전달train.samples규약 ⑤
⑭학습 Job이 모델 파일을 GCS에 저장LightGBM 모델 파일그림의 train_model
⑮학습 Job이 실험 기록과 버전을 MLflow에 등록파라미터, 지표, 모델 버전그림의 train_model
⑯MLflow가 모델 파일 위치를 참조GCS 경로그림의 MLflow
⑰추론 서버가 켜질 때 Production 모델 위치를 조회모델 버전, GCS 경로그림의 점수화 모델
⑱추론 서버가 모델 파일을 받아 메모리에 올림모델 파일그림의 점수화 모델

② 뉴스 백엔드 → 추론 서버

백엔드가 후보를 보내면 추론 서버가 점수와 순위만 돌려준다. 계속 변하는 값은 추론 서버가 Valkey에서 읽는다.

항목값
주소POST /v1/rank (GKE 내부 서비스 주소, 외부 공개 안 함)
응답 시간추론 서버 목표 p95 100ms (멘토님 0.1초 기준). 백엔드 타임아웃 500ms(팀 자료 값, 부하 테스트로 조정)
보조GET /healthz: 프로세스가 살아 있으면 200. GET /readyz: 모델을 올리고 Valkey에 연결됐을 때만 200 (롤링 교체 때 GKE가 본다, #2). GET /v1/model: 지금 올라간 model_version

응답 필드

필드타입뜻
request_idstring요청 값 그대로
model_versionstringMLflow 등록 이름@버전 (예: pctr@7). 백엔드는 반환 기록에 그대로 싣는다
features_as_ofstring읽은 Valkey 피처가 몇 시 기준인지 (예: 2026-11-03T08:00:00+09:00). 학습의 포인트 인타임 조인 규칙과 같은지 점검하는 용도

⑥ Valkey 키 구조

export_serving이 매시 새 버전 키를 쓰고 포인터만 바꾼다.

키자료형필드 / 값
feat:currentSTRING현재 버전 = 스냅샷 시각 한국 시간 YYYYMMDDHH (예: 2026110308). 응답의 features_as_of가 이 값이다. 만료 없음
rf:{ver}:{reader_id}HASHcat_prefs (JSON: {"경제": [open_ratio, ctr, like_ratio], ...}), recent5_categories (JSON 배열), ctr_30d, active_days_30d, active_hour_ratio (JSON 24칸), emb (float32 768개 바이트)
af:{ver}:{article_id}HASHcategory, published_at (epoch 초), opens_1h, ctr_1h, likes_1h, clickbait_score, emb (float32 바이트)
re:{ver}:{reader_id}HASH필드 = article_id, 값 = 유효 exposure 횟수
ri:{ver}:{reader_id}HASH필드 = article_id, 값 = impression 횟수
popular:{ver}ZSET멤버 = article_id, 점수 = 최근 1시간 열기 수. 백엔드가 후보·대체 응답을 인기순으로 고를 때 읽을 수 있다 (선택)
  • 숫자 값: HASH 값은 10진수 문자열. 모르는 값은 필드를 쓰지 않고, 추론 서버는 없는 필드를 결측으로 읽는다.
  • 만료: 버전이 붙은 키는 3시간 뒤 만료 (EXPIRE 10800). 포인터를 바꾼 뒤 이전 버전을 읽던 요청이 끝날 시간을 준다.
  • 신규 독자·새 기사: 키가 없으면 해당 피처를 결측으로 두고 점수는 낸다. 응답 defaulted에 이유를 적는다.
  • 복구: 같은 값을 GCS serving/{ver}/에 Parquet로 남긴다. Valkey를 다시 띄우면 마지막 버전을 그 파일에서 채운다.
