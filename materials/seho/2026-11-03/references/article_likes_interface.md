# 좋아요 데이터 인터페이스

프론트와 뉴스 서버 사이의 좋아요 등록·취소 및 조회 규약이다.
JSON의 데이터 키는 첨부된 `article_likes` 컬럼명인 `user_id`, `article_id`, `liked_at`을 사용한다.

## 1. 좋아요 등록

**프론트 → 뉴스 서버**


요청 JSON:

```json
{
  "user_id": "u001",
  "article_id": "A"
}
```

| 요청 키 | 형식 | 설명 |
| --- | --- | --- |
| `user_id` | string | 프론트가 생성·보관한 익명 사용자 ID |
| `article_id` | string | 뉴스 목록 응답에서 받은 대상 기사 ID |

성공 응답: `200 OK`

```json
{
  "user_id": "u001",
  "article_id": "A",
  "liked_at": "2026-11-03T13:12:29+09:00"
}
```

| 응답 키 | 형식 | 설명 |
| --- | --- | --- |
| `user_id` | string | 좋아요한 사용자 ID |
| `article_id` | string | 좋아요한 기사 ID |
| `liked_at` | string, ISO 8601 | 서버가 반환하는 좋아요 설정 시각. 예: `2026-11-03T13:12:29+09:00` |

이미 좋아요가 등록된 경우에도 같은 형식으로 현재 좋아요 정보를 반환한다.

## 2. 좋아요 취소

**프론트 → 뉴스 서버**


요청 JSON:

```json
{
  "user_id": "u001",
  "article_id": "A"
}
```

| 요청 키 | 형식 | 설명 |
| --- | --- | --- |
| `user_id` | string | 프론트가 보관한 익명 사용자 ID |
| `article_id` | string | 좋아요를 취소할 기사 ID |

성공 응답: `204 No Content`

응답 본문은 없다. 이미 좋아요가 없는 경우에도 동일하게 응답한다.

## 3. 사용자별 좋아요 조회

**프론트 → 뉴스 서버**


요청 항목:

| 키 | 형식 | 의미 |
| --- | --- | --- |
| `user_id` | string | 좋아요 목록을 조회할 사용자 ID |

성공 응답: `200 OK`

응답 본문은 좋아요 기록의 JSON 배열이다.

```json
[
  {
    "user_id": "u001",
    "article_id": "A",
    "liked_at": "2026-11-03T13:12:29+09:00"
  },
  {
    "user_id": "u001",
    "article_id": "B",
    "liked_at": "2026-11-03T13:15:00+09:00"
  }
]
```

| 응답 배열의 키 | 형식 | 설명 |
| --- | --- | --- |
| `user_id` | string | 좋아요한 사용자 ID |
| `article_id` | string | 좋아요한 기사 ID |
| `liked_at` | string, ISO 8601 | 좋아요 설정 시각 |

좋아요한 기사가 없으면 빈 배열을 반환한다.

```json
[]
```

프론트는 응답의 `article_id` 목록과 뉴스 목록의 `article_id`를 비교해 좋아요 표시를 한다.
별도의 `liked` 키는 사용하지 않는다.

## 4. 호출 흐름

```text
뉴스 목록 표시 → 해당 user_id의 좋아요 목록 조회 → article_id를 비교해 표시
좋아요 선택   → 등록 요청 → 성공 응답 확인 후 선택 표시
좋아요 취소   → 취소 요청 → 성공 응답 확인 후 선택 해제
```

이 문서는 데이터 인터페이스 정의이며, 구현 완료를 의미하지 않는다.
